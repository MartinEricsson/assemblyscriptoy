## Dependency notes

- 001 lands first because every later plan needs a reliable shader-corpus,
  browser-smoke, and production-bundle gate.
- 002 lands before 003 because both modify the animation/session lifecycle in
  `src/main.js`; the CPU error path should be built on the final ownership
  model rather than merged into code that is about to change.
- 004 depends on 001 so removal of the pre-build path is protected by the new
  production-bundle and browser checks.
- 005 follows 004 because both update `package.json`, `pnpm-lock.yaml`, and the
  production bundle. Sequential execution avoids unnecessary lockfile and
  script conflicts.
- 006 depends on the verification and session-ownership work from 001 and 002.
  It has an additional external dependency: an upstream `@gasm-compiler/core`
  release with dynamic `i32.atomic.rmw.add`, atomic-region preparation, and
  per-entry-point dispatch metadata must land before the downstream 100K demo
  can be completed.
- 007 is independent of 006. It depends in spirit on the One Weekend demos
  already on `main` (`9e49fbf`) and on the corpus gate from 001, but it does
  not wait on the SPH compiler work.
- 008–012 are algorithmically independent of each other and of 006. They all
  insert a `compiler` group entry immediately before `rtowImage` and bump
  the README demo counts, so run them **in numeric order** on one branch to
  avoid catalog/README merge conflicts. Separate branches must rebase.
- 008–012 do not wait on Gasm atomics or multi-export dispatch. Do not
  collapse them into plan 006's 100K SPH work.

## Deferred findings

- Generate the sidebar, hidden select, and browser-demo list from one manifest.
  Valuable, but separate from the correctness and verification work in this
  batch.
- Include the entry point in the GPU pipeline cache key. The application only
  uses `main` today, so this is a lower-impact API-hardening task.
- Synchronize tab visibility with `aria-selected`. Important accessibility
  cleanup, but it does not block the compiler/render workflow.
- Build artifact export and a compiler-conformance dashboard are product
  direction options, not maintenance prerequisites.
- A dedicated Next Week BVH demo (visually identical to motion blur) and a
  host-packed 1000-sphere final scene were considered for plan 007 and
  deferred: Gasm parallelizes the pixel loop, so a one-time tree build cannot
  live in `main()`, and `photoreal_mesh_path_tracer` already shows a packed
  BVH. The unreduced book final scene is a follow-up, not a 007 blocker.
- In-shader BVH **construction** (then trace) was considered as a sixth
  compiler demo and deferred: it needs the same staged cell-owned build as
  SPH, collides with photoreal's host packer story, and still cannot be a
  one-time tree build inside a parallel `main()`. Revisit after 006 if
  multi-export dispatch lands.
- Choppy Tessendorf displacement, perspective-correct raster attributes,
  4-wide SIMD shadows, and Instant-NGP hash encodings are listed as
  follow-ups inside 009 / 010 / 008 / 012 and are not separate plans.

## Findings considered and rejected

- Upgrade Vite 5 directly to Vite 8 in this batch: rejected because it changes
  the Node support floor and should be a dedicated migration with its own
  browser and deployment validation.
- Add a broad CSP in the Prism plan: rejected for this batch because the page
  currently relies on inline handlers, inline styles, Google Fonts, and dynamic
  compiler chunks. Bundling executable CDN scripts is a focused first step;
  CSP needs a separate design and migration.
- Another path-tracer or Ray Tracing book chapter: rejected for 008–012
  because the catalog is already ~40% ray/path tracing after 007.
- Gerstner-only ocean or a second SIMD kaleidoscope: rejected because they
  would not add WAT/WGSL evidence beyond demos already on `main`.
- Relabeling 8K Grid SPH into the compiler sidebar group: talk-script only,
  not a new demo.
- MPM / lattice Boltzmann / FEM / N-body: already captured in
  `docs/physics-demos-roadmap.md`; they are numerical-method gallery items,
  not this compiler-capability batch.
